# VivaTech replay discovery notes

These notes come from the June 2026 VivaTech replay extraction session.

## What worked

### Authenticated browser + VPN/profile

- The user could browse manually, especially after switching VPN.
- Starting Chrome with the user's profile worked better than fresh automation:
  ```bash
  /Users/pschuermann/.claude/skills/browser-tools/browser-start.js --profile
  ```
- Once `/replay` was unlocked with the user's email, the page showed `2026 Sessions On Demand` and embedded all replay metadata in the HTML.

### Save replay HTML from inside the authenticated browser

Direct HTTP requests from the shell returned GTAB `403`, but in-page fetch inside the browser context worked:

```js
const html = await page.evaluate(async () =>
  await (await fetch('/replay', { credentials: 'include' })).text()
)
```

This captured ~2 MB of HTML with 226 `replayUrl` entries.

### Replay URL → Dailymotion video ID

Each replay object has:

```json
"replayUrl": "https://geo.dailymotion.com/player.html?video=xah889i&no_expire=1&no_ip_lock=1"
```

Extract the `video` query parameter (`xah889i`). The Dailymotion page for the same video is:

```text
https://www.dailymotion.com/video/xah889i
```

### Dailymotion metadata exposes subtitle URLs

Metadata endpoint:

```text
https://www.dailymotion.com/player/metadata/video/<video_id>
```

For `Second Order AI` / `xah889i`, it returned:

```json
"subtitles": {
  "enable": true,
  "data": {
    "en-auto": {
      "label": "English (autogenerated)",
      "urls": ["https://static2.dmcdn.net/.../633599190_subtitle_en-auto.srt"]
    }
  }
}
```

Fetching that SRT URL produced a complete timestamped transcript.

### Program/session discovery

- `/sessions` pages lazy-load; scroll to discover more cards.
- Filters are usable in the DOM; day filters become URLs like `/sessions?days=2026-06-19`.
- DOM extraction worked:
  ```js
  document.querySelectorAll('a[href*="/sessions/session/"]')
  ```
- Session detail pages contain rich metadata and JSON-LD. Example fields: title, start/end time, location, description, tags/tracks, speaker names, speaker links, and `Watch Replay` marker.
- Clicking `Watch Replay` on a session page can append a replay login panel. The more scalable source is still `/replay` after unlock.

## What did not work / be careful

### Direct curl/Python to VivaTech

Direct requests to `https://vivatech.com/...` returned:

```text
403 Forbidden | GTAB Security
Access Denied | GTAB Security
```

Repeated probing probably worsens blocking. Avoid bulk direct requests to VivaTech.

### Fresh Playwright/headless browser

Fresh Playwright/Chrome hit the same GTAB block. Use the normal user profile and avoid suspicious fresh profiles unless necessary.

### FlareSolverr

FlareSolverr was running and healthy, but fetching VivaTech through it returned the same GTAB access-denied HTML. It is not a solution for this site.

### Jina Reader

`r.jina.ai` could fetch public session pages and convert them to Markdown even when local direct fetches were blocked. It was useful for public metadata discovery, but it is a third-party proxy/reader:

- OK for public pages if the user agrees.
- Do not send private replay pages, cookies, login state, or email-gated content through it.

### Search box / React input gotchas

Setting React-controlled inputs via raw `element.value = ...` may not update state. Use native setters + input events when needed:

```js
const setter = Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set
setter.call(input, value)
input.dispatchEvent(new InputEvent('input', { bubbles: true, inputType: 'insertText', data: value }))
```

For replay search, URL query state sometimes became double-encoded (`search=Second%2520Order%2520AI`), so don't depend on search alone for exhaustive extraction.
